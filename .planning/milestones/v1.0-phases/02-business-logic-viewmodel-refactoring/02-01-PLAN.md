<objective>
Extract all quiz business logic from `QuizViewModel` into pure-Kotlin domain UseCases (per locked decision: dedicated Use Cases per flow, ARCH-04). This plan delivers the domain half of the phase: quiz-type models relocated to the domain module, four UseCases with full unit-test coverage, and a Wave-0 test harness (hand-rolled fakes, coroutines-test). Purpose: QuizViewModel is currently a 682-line god object mixing session loading, answer evaluation, XP rules, FSRS scheduling, and completion rules. Isolating this logic in the domain module makes it unit-testable without Android context and keeps the ViewModel lean (per D-Quiz-Logic-Extraction in 02-CONTEXT.md).

Output: `domain.model.quiz` package (moved types), 4 UseCases + 4 test classes + 3 fakes, green `:domain:test`, app still compiling against moved types.
</objective>
