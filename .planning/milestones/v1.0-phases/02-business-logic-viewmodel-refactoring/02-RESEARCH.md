The ViewModel maps these to UI strings (or `UiText` wrappers).\n\n### Pitfall 2: Overloading SavedStateHandle\n**What goes wrong:** Trying to save large objects (like the entire list of `QuestionWithCard`) into `SavedStateHandle`.\n**Why it happens:** Misunderstanding that `SavedStateHandle` serializes data to a Bundle, which has strict size limits (~500kb).\n**How to avoid:** Only save IDs (e.g., `nodeId`, `sessionIndex`, `currentIndex`). Re-fetch the actual data from the database/UseCase upon restoration.\n\n### Pitfall 3: Swallowing Exceptions in UseCases\n**What goes wrong:** Wrapping repository calls in `try/catch` and returning null, hiding the real error from the UI.\n**Why it happens:** Trying to prevent crashes without proper error modeling.\n**How to avoid:** Ensure UseCases return `Result<T>` and explicitly map exceptions to Domain Errors, allowing the ViewModel to emit an `UiState.Error`.\n\n## Code Examples\n\n### Refactored UseCase Pattern\n```kotlin\nclass SubmitReviewUseCase @Inject constructor(\n    private val reviewRepository: ReviewRepository,\n    private val settingsRepository: SettingsRepository,\n    private val mapRatingUseCase: MapRatingUseCase\n) {\n    suspend operator fun invoke(\n        card: Card, \n        rating: Rating, \n        isCorrect: Boolean, \n        responseTimeMs: Long\n    ): Result<Card> = runCatching { \n        // Extract logic from QuizViewModel lines 570-585 here\n        // Return updated card\n    }\n}\n```\n\n## Environment Availability\n\nStep 2.6: SKIPPED (no external dependencies identified.
