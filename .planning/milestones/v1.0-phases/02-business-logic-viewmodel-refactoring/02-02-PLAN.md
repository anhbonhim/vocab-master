<objective>
Refactor `QuizViewModel` into a lean UDF ViewModel (ARCH-03) that consumes the Plan-01 UseCases: single immutable `QuizUiState` sealed interface exposed as one `StateFlow` (per locked decision D-UI-State), `SavedStateHandle`-backed session survival (per locked decision D-SavedState), synchronous guards against rapid double-submission, and explicit `Error` state emission on any UseCase failure. QuizScreen call sites are updated to the new state type; no layout/visual changes (screen decomposition is Phase 3, ARCH-01 — explicitly out of scope here).

Purpose: Enforce exhaustive state handling at compile time, eliminate the god-object ViewModel, and make quiz progress survive configuration change + process death with lightweight persisted keys.

Output: QuizUiState.kt, rewritten QuizViewModel (~200 lines, down from 682), updated QuizScreen.kt, JVM ViewModel tests (no Robolectric), human checkpoint for on-device rotation/regression pass.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| UI events → ViewModel | Untrusted timing (rapid taps, double submission) crosses into scheduling logic. |
| ViewModel → SavedStateHandle → OS Bundle | State serialized by the OS; size-limited and process-death-exposed. |
| UseCase Result → UI state | Failure info must surface to the user, not be swallowed. |
