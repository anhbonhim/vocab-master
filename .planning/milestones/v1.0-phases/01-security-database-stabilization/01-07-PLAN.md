<objective>
Replace dynamic, unsafe JSON asset-parsing fallbacks in repositories with robust error handling and specific exception catching (PERS-04; D-24, D-25, D-26, D-27).

Purpose: Today a corrupt options/matchingPairs/guidebook JSON column silently becomes null/empty data; a corrupt backup import prints a stack trace and returns false with no diagnosis. After this plan, parse failures are typed, logged, and propagated as `Result.failure` — the error-handling convention Phase 2 (ViewModels) and Phase 3 (UI) will build full UiState.Error surfaces on.
Output: `VocabDataException` + Result-returning repository decoders + folded call sites + Robolectric failure-injection tests.
</objective>

</threat_model>
