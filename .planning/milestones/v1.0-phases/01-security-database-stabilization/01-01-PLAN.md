<ground_truth_decisions>
Two conflicts between CONTEXT.md and the installed py-fsrs 6.3.1 ground truth were found during planning. Both are resolved in favor of ground truth (which is what the golden vectors are generated from — following the literal CONTEXT text would make the test suite fail against itself):

1. **D-06 parameter discrepancy (IMPORTANT):** CONTEXT D-06 lists `DEFAULT_PARAMETERS[0] = 0.2172`. The installed py-fsrs 6.3.1 (latest on PyPI, verified via `pip index versions fsrs`) ships `DEFAULT_PARAMETERS = (0.212, 1.2931, 2.3065, 8.2956, 6.4133, 0.8334, 3.0194, 0.001, 1.8722, 0.1666, 0.796, 1.4835, 0.0614, 0.2629, 1.6483, 0.6014, 1.8729, 0.5425, 0.0912, 0.0658, 0.1542)`. D-05's intent ("matches the current py-fsrs default") governs: the port MUST use **0.212** so Kotlin output matches vectors generated from the same package. Document this deviation in a KDoc comment on the constant.

2. **State.New reconciliation:** py-fsrs has only Learning(1)/Review(2)/Relearning(3); a pristine card is `Learning` with `step=0`, `stability=null`, `difficulty=null`. D-09 mandates a 4-value enum (New/Learning/Review/Relearning). Resolution: v6 `State` keeps all four with legacy int values (New=0, Learning=1, Review=2, Relearning=3) for DB/UI compatibility; `State.New` is EXACTLY the py-fsrs pristine card (Learning-branch semantics, step=0, null S/D). `reviewCard` handles New via the Learning branch; after any first review the card becomes Learning/Review (never returns to New). Golden-vector mapping rule: JSON `state="Learning"` + `step=0` + `stability=null` + `difficulty=null` maps to v6 `State.New`; all other snapshots map by name.

Additional documented port decisions:
- **Epoch-millis model:** v6 `Card.due: Long`, `Card.lastReview: Long?`, `ReviewLog.reviewDatetime: Long` are UTC epoch millis (D-09). This makes py-fsrs's UTC-awareness `ValueError` unreachable by construction. Day deltas: `(laterMillis - earlierMillis) / 86_400_000` (matches Python `timedelta.days` floor for positive deltas; clamp at 0 where py does `max(0, ...)`).
- **Banker's rounding:** Python `round()` is round-half-to-even. Kotlin MUST use `kotlin.math.round(x)` (ties-to-even) — NOT `roundToInt()` (half-up) — in `_nextInterval` and `_getFuzzRange`, or Int-field golden assertions (D-15 exact equality) will drift on .5 ties.
- **reps/lapses metadata:** py-fsrs Card has no reps/lapses, but VocabMaster UI (MistakeBankTab, StatisticsViewModel) consumes them. v6 `Card` carries `reps: Int = 0` and `lapses: Int = 0` as non-math metadata: `reviewCard` increments `reps` by 1 and `lapses` by 1 iff previous state == Review && rating == Again (mirrors legacy behavior). The scheduler math never reads them. Documented deviation; golden vectors ignore these fields.
- **cardId type:** v6 uses `String` (app identity is questionId) instead of py's int; identifier type does not affect math. Serde keeps py JSON key names (`card_id`, `review_datetime`, `review_duration`).
</ground_truth_decisions>
