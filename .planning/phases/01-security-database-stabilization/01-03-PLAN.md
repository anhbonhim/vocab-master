<port_constraints>
Documented deviations from py-fsrs's optimizer (all required — py depends on torch/pandas/tqdm which have no Kotlin equivalents):
1. **Finite-difference gradients replace torch autograd.** Central difference per parameter: `grad_i = (loss(w + h_i·e_i) − loss(w − h_i·e_i)) / (2·h_i)` with `h_i = 1e-4 * max(|w_i|, 0.01)`. Everything else about the training loop (Adam updates, cosine annealing, mini-batching, bounds clamping, best-by-epoch-loss selection) follows py-fsrs exactly. Document in KDoc.
2. **No torch tensor detachment semantics.** After each mini-batch gradient step, py detaches the in-flight card's stability/difficulty from the graph; with numerical gradients this is a no-op — recreate the Scheduler with updated parameters after each step (same as py).
3. **Shuffle RNG:** py uses `random.Random(42)`; Kotlin uses `kotlin.random.Random(42)` with `list.shuffle(Random(42))` per epoch. Shuffle order will differ from Python — training trajectories are therefore not bit-identical, so optimizer tests assert PROPERTIES (defaults guard, bounds, loss decreases, validation errors), never exact trained values.
4. **No pandas/tqdm:** `_compute_probs_and_costs` is plain Kotlin maps/lists; no progress bar.
5. **computeOptimalRetention return type:** py declares `list[float]` but returns a single float — port returns `Double`.
</port_constraints>
