## Accomplishments

- **Async LLM client (CONT-02 foundation, threat T-05-03):** `app/services/llm_service.py` exposes `generate_exercises_from_llm(words)` using `httpx.AsyncClient` (per plan must_haves prohibition of `requests` / sync `httpx.Client`), with a configurable 60-second timeout sourced from `settings.OPENCODE_TIMEOUT_SECONDS`. `httpx.TimeoutException` and `httpx.HTTPStatusError` are caught and re-raised as the canonical `LLMServiceError` so callers only need to catch one type. ## Decisions Made

- **`httpx.AsyncClient` is referenced as `httpx.AsyncClient(...)` (attribute lookup) rather than a top-level `from httpx import AsyncClient`.** This lets the test suite swap the client via `monkeypatch.setattr("app.services.llm_service.httpx.AsyncClient", ...)` without monkey-patching the global `httpx` module. The plan's must_haves explicitly forbids `requests`; this design also forbids accidentally using the sync `httpx.Client` because the tests would fail to await.
- **Defensive empty-API-key guard.** Even though the `Settings` class defaults `OPENCODE_API_KEY` to `""`, the service explicitly checks for it before issuing any HTTP call. Without this, a misconfigured deployment would make a real request to Opencode with `Authorization: Bearer ` (no key), which would either get rejected as 401 or — worse — succeed if Opencode treats it as an anonymous request. Failing fast at the service boundary is safer.
- **Service returns raw text, not parsed JSON.** The whole point of `validate_llm_output` being the single chokepoint (T-05-02) is that no AI-generated content reaches the DB without Pydantic validation. If the service parsed the JSON itself, there would be two code paths and a developer could accidentally skip validation. Returning raw text forces the caller to go through the chokepoint.
- **Empty-vocabulary short-circuit.** If `fetch_vocabulary_words(db, topic)` returns `[]`, the script returns 0 BEFORE calling the LLM. This is a Rule 2 (missing critical) auto-fix: calling the LLM with an empty list would produce a malformed prompt and waste tokens, AND could result in the LLM returning a generic "list of words" response that has nothing to do with the operator's intent. Aborting early is the only safe behavior.
- **CLI exit codes 0/1, not arbitrary numbers.** 0 = success, 1 = any failure. Operators can pipe the exit code into shell scripts / cron emails without remembering custom codes. Documented in the module docstring.
- **Settings must be patched in TWO modules.** `app.services.llm_service` does `from app.config import settings` at import time, so the imported binding is a separate name in the service module's namespace. The autouse fixture and the test that overrides env vars both patch BOTH `app.config.settings` AND `app.services.llm_service.settings`. This is a non-obvious quirk of Python's import system that future test authors will benefit from seeing documented.
- **Integration tests over a pure smoke check for Task 2.** The plan's `verify` command is just `python -m py_compile`, which proves only that the file is syntactically valid — not that the pipeline actually wires correctly. The plan's `acceptance_criteria` is "Pipeline correctly wires LLM fetch, validation, and DB save" — that requires a real test, not a compile check. The 9 integration tests prove the wiring end-to-end and are a Rule 2 (missing critical test) auto-fix.

**2. [Rule 1 - Bug] `_StubAsyncClient` initially forgot to set `response._request`, breaking `raise_for_status`**
- **Found during:** Task 1 GREEN — first test run
- **Issue:** httpx's `Response.raise_for_status()` requires the originating request to be set on the response. `httpx.MockTransport.handle_request` returns a bare `Response` without `._request`, so `client.post(...).raise_for_status()` raised `RuntimeError("Cannot call \`raise_for_status\` as the request instance has not been set on this response.")`.
- **Fix:** In `_StubAsyncClient.post`, after the transport returns a response, set `response._request = request` (httpx private attribute — but it's the documented way to satisfy `raise_for_status` in mocked scenarios). All 6 LLM service tests then passed.
- **Files modified:** `backend/tests/test_llm_service.py`.
- **Verification:** `pytest tests/test_llm_service.py` — 6/6 pass.
- **Committed in:** `0e137bf` (Task 1 GREEN commit).

**3. [Rule 3 - Blocking] Autouse fixture had to patch BOTH `app.config.settings` AND `app.services.llm_service.settings`**
- **Found during:** Task 1 GREEN — 5 of 6 tests still failed after the first autouse fixture
- **Issue:** The service does `from app.config import settings` at import time, which makes `app.services.llm_service.settings` a separate name binding. Patching only `app.config.settings` (which the autouse fixture originally did) is invisible to the service — it still sees the old Settings instance with the empty `OPENCODE_API_KEY` and refuses to make the call.
- **Fix:** Updated the autouse fixture (and the two tests that override env vars) to patch BOTH module bindings. This is now a documented pattern in the SUMMARY ("Settings must be patched in TWO modules").
- **Files modified:** `backend/tests/test_llm_service.py`.
- **Verification:** `pytest tests/test_llm_service.py` — 6/6 pass.
- **Committed in:** `0e137bf` (Task 1 GREEN commit).

**4. [Rule 1 - Bug] `_SessionHolder` initially wrapped the session in a proxy but the script calls `db.close()` on the SessionLocal return value, not on the proxy**
- **Found during:** Task 2 — first test run of the content gen integration test
- **Issue:** The original design was `SessionLocal() -> _SessionProxy(real_session)`, but the script does `db = SessionLocal(); ...; db.close()`, so `close()` is called on the proxy (correct) BUT the test was using `monkeypatch.setattr("...content_gen.SessionLocal", lambda: _SessionHolder(db_session))` which returned the holder, not the proxy — so `db.close()` raised `AttributeError: '_SessionHolder' object has no attribute 'close'`.
- **Fix:** Made `_SessionHolder` itself BE the session (with `query`, `commit`, `refresh`, `close` as forwarding methods) and removed the separate `_SessionProxy` class. Simpler and correct.
- **Files modified:** `backend/tests/test_content_gen.py`.
- **Verification:** `pytest tests/test_content_gen.py` — 9/9 pass.
- **Committed in:** `6bbb9ed` (Task 2 commit).

## User Setup Required

**`OPENCODE_API_KEY` must be set before the content script can be run for real.** The script logs a clear error and exits 1 if the key is empty (defensive guard), so an operator who forgets to set it gets an actionable message rather than a silent 401 from Opencode.

- **Where it goes:** `backend/.env` (read by pydantic-settings) or as a real environment variable when the script is invoked.
- **How to get one:** Per the D-02 decision, the backend talks to the Opencode go API directly (not OpenAI/Gemini/Claude). The procurement flow is documented in the Opencode deployment docs (out of scope for this plan).
- **No action required from this plan** — the empty-string default keeps the app bootable, the LLM service refuses to call, and the CLI exits 1 with a clear message.
